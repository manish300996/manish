Chapter 05

6-month sprint — month by month + resources

Job ke saath 10–12 hours / week. Weekend pe 5–6 hours project. Weeknights 60–75 min SQL/Spark/design. Certificate last, GitHub first.

Weeks 1–4 · no new shiny tools
Month 1 — Foundation reset (senior bar)

Goal: SQL + Python + modeling itne tight ho ki product round 1 clear. Resume v1 live. Numbers homework complete.

SQL — expert checklist

  • Window functions: RANK/DENSE_RANK, LAG/LEAD, running totals, sessionization
  • Gaps-and-islands, top-N per group, dedupe, SCD2 query patterns
  • JOIN types including anti-join / semi-join; EXISTS vs IN
  • Incremental load: MERGE / INSERT OVERWRITE partitions
  • Tuning: EXPLAIN, partition pruning, clustering/clustering keys, file skip

Python — pipeline, not notebook

  • Functions, pathlib, logging, retries (tenacity), argparse
  • pytest for transforms; type hints; virtualenv
  • Small API ingest script with backoff + schema check

Resources

  • Mode SQL Tutorial — rewrite mentally as “I already know this, speed-run”
  • Select Star SQL — windows
  • LeetCode Database — 80–100 Q, hard included (5 YOE bar)
  • Use The Index, Luke — plans / indexes
  • Book: The Data Warehouse Toolkit (Kimball) — star / SCD chapters only
  • pytest docs + Real Python — logging, pathlib
  • Practice warehouse: SQLPad / HackerRank SQL advanced

Milestone: 40 LeetCode DB done · 1-page modeling of your current job’s core fact · Resume v1 on LinkedIn.

Weeks 5–12
Month 2–3 — Spark performance (salary engine)

Goal: “I can read Spark UI and fix a slow job” — yeh sentence interview mein proof ke saath. Syntax wale DE 18 LPA. Tuner 30+.

Deep list (is sequence mein)

  1. Driver vs executor, cores, partitions, tasks, stages
  2. Narrow vs wide; shuffle write/read; exchange in plan
  3. Parquet layout, 128–256 MB files, too-small files problem
  4. Partitioning vs bucketing; when not to partition on high-cardinality
  5. Joins: broadcast vs sort-merge; skew (salting, AQE skew join)
  6. AQE, adaptive coalescing, dynamic partition pruning
  7. Caching vs checkpoint; spill to disk; OOM patterns
  8. Delta Lake: MERGE, Z-order/OPTIMIZE, vacuum, time travel

Resources

  • Spark SQL programming guide
  • Book: Learning Spark (O’Reilly, 2nd ed.) — chapters on SQL, joins, tuning
  • Databricks Spark optimization guide
  • Delta Lake docs
  • YouTube: Spark UI walkthroughs (Databricks official + SparkByExamples for API only)
  • Dataset: NYC TLC trip data / GitHub archive — 10GB+ compulsory

Spark — expected answers (short, exact)

Shuffle

Wide transformation se data exchange across executors. Costly due to disk + network. Reduce: pre-filter, broadcast small side, partition for join keys, AQE.

Skew

One key explodes a partition. Symptoms: one task 10× longer. Fixes: salting, skew join (AQE), isolate hot key, two-phase agg.

Broadcast join

Small table fits executor memory (and spark.sql.autoBroadcastJoinThreshold). Huge table nahi broadcast. After filter, stats matter.

Small files

Thousands of tiny Parquet files = slow listing + tasks. Compact to ~128MB. coalesce vs repartition trade-off (shuffle).

System design template (har question pe yeh order)

  1. Clarify: sources, volume (peak), latency SLA, retention, consumers (BI vs ML vs product), exactly-once need?
  2. Grain + model: facts/dims, keys, SCD, late data policy
  3. Batch vs stream vs CDC: say when batch wins (cheaper, simpler)
  4. Architecture: ingest → bronze → silver → gold; queue; warehouse; serving
  5. Reliability: retries, DLQ, idempotent sinks, replay from Kafka/offset or partition reload
  6. DQ + observability: tests, freshness alerts, lineage, on-call
  7. Cost + security: compute isolation, partition pruning, PII, IAM
  8. Scale 10×: what breaks first

Sample STAR (ratlo, numbers apne se)

Situation: Finance dashboard missed 08:00 SLA 4 times in a month. Job “fnl_orders_enrich” ran 4.5h, often after 08:20. Cluster cost also spiked. Task: I owned the job. Need < 60 min, same numbers, no extra budget. Action: Spark UI showed 1 skewed stage (join on country=IN, 70% rows). Enabled AQE skew join, broadcast the 80MB dim, wrote 128MB Parquet instead of 12k tiny files, switched full refresh to MERGE on order_date (3-day lookback). Added duration + row-count alerts. Result: 4.5h → 42m. SLA green for 8 weeks. Cluster hours −41%. This is the story I tell in every Spark round.

Airflow / dbt / Kafka one-liners they love

  • Idempotent DAG: rerun same day = same tables, no duplicates (partition overwrite or MERGE keys).
  • Catchup vs backfill: catchup auto-runs missed intervals (dangerous); backfill is controlled.
  • dbt incremental: unique_key + lookback window; know when to full-refresh.
  • Kafka exactly-once: producer idempotence + transaction or sink idempotency (MERGE); “at-least-once + dedupe” often practical.
  • Consumer group: scale = partitions ≥ consumers; lag = production KPI.
